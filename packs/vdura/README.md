# VDURA PanFS packs for Spectro Cloud Palette

Two Palette add-on packs that deploy the VDURA PanFS CSI driver:

| Pack | Version | What it deploys |
|---|---|---|
| [`vdura-panfs-csi`](packs/vdura-panfs-csi-1.2.5/README.md) | 1.2.5 | VDURA's upstream `csi-panfs` and `csi-panfs-storageclass` Helm charts, plus a small chart that creates the private-registry pull secret |
| [`kernel-module-management`](packs/kernel-module-management-2.7.0/README.md) | 2.7.0 | The KMM operator, which the driver uses to load the `panfs` kernel module on client nodes |

Cluster profile add-on layers, bottom to top:

1. cert-manager (from the Palette registry)
2. Kernel Module Management (KMM)
3. VDURA PanFS CSI Driver

## What you need from VDURA

- Credentials for the private registry that serves the `panfs-dfc` and `panfs-kmm` images.
- The DFC release version, and confirmation that it is supported with driver 1.2.5. Driver 1.2.5 loads the encryption module as `libwolfssl` and reads the `storageset` StorageClass parameter, where 1.2.3 used `wolfssl` and `bladeset`. See the [pack README](packs/vdura-panfs-csi-1.2.5/README.md#prerequisites).
- Confirmation that `panfs-kmm` images exist for the exact kernel your Palette nodes run. KMM picks the image by kernel version, and the default mapping matches RHEL-family x86_64 kernels.

## Layout

```
packs/
  vdura-panfs-csi-1.2.5/            pack.json, values.yaml, README.md, logo.png, charts/*.tgz
  kernel-module-management-2.7.0/   pack.json, values.yaml, README.md, logo.png, charts/*.tgz
charts-src/
  csi-panfs-registry-secret/        helper chart that creates the image pull secret
  kernel-module-management/         KMM wrapper chart; templates/ is generated by build.sh
scripts/
  build.sh                          rebuilds charts/*.tgz from pinned upstream tags and writes dist/
  validate.sh                       offline checks: structure, helm lint/template, image lists
dist/                               uploadable <name>-<version>.tar.gz pack archives
```

## Build and validate

```bash
./scripts/build.sh
```

```bash
./scripts/validate.sh --images
```

`build.sh` clones the VDURA driver at tag `1.2.5` and KMM at `v2.7.0`, packages the charts into the packs, and writes the archives to `dist/`. `validate.sh` never contacts a cluster. It renders each chart with the pack values and placeholder answers for the required fields. `--images` also confirms every listed image exists (needs `crane`).

## Publish to a Palette pack registry

For an OCI pack registry (Harbor, Zot, ECR, and so on), push each archive under the `spectro-packs/archive` path that Palette expects:

```bash
oras push "$REGISTRY/spectro-packs/archive/vdura-panfs-csi:1.2.5" dist/vdura-panfs-csi-1.2.5.tar.gz
```

```bash
oras push "$REGISTRY/spectro-packs/archive/kernel-module-management:2.7.0" dist/kernel-module-management-2.7.0.tar.gz
```

Then add the registry in Palette under **Tenant Settings > Registries > OCI Registries**, with type **Pack**. Spectro's docs on [adding packs to an OCI registry](https://version-4-1.legacy.docs.spectrocloud.com/registries-and-packs/oci-registry/add-pack-oci/add-pack-oci-basic) list the required ORAS version and the per-registry steps.

## Changes from upstream

- **Sidecar images.** They use `registry.k8s.io` at the same versions, instead of the frozen `k8s.gcr.io` and the `k8s-staging-sig-storage` registry.
- **Client node label.** Nodes are selected by `panfs.csi.vdura.com/client=true` instead of `node-role.kubernetes.io/worker`, which kubelets cannot set on themselves. Set the label through Palette node pool labels.
- **Pull secret.** It is created by the pack. Upstream expects a manual `kubectl create secret`.
- **No `{{ }}` in pack values.** Palette uses `{{ }}` for its own macros, so the upstream values that used Helm-style placeholders are spelled out. As a result, the KMM kernel mapping repeats the registry and DFC version.
- **KMM images.** They are pinned to the builds of the v2.7.0 release commit, because KMM publishes only `:latest` and date-stamped tags.

Spectro's pack-central values check flags the two `panfs.csi.vdura.com/client` selector keys, because they are not in the upstream chart's values. Every other pack-central check passes.

## Status

The packs build, lint, and render cleanly offline, and every public image they reference exists. They have not been deployed to a live Palette cluster yet.
